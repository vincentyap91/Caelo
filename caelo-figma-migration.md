## CONTEXT

The Caelo codebase has a two-layer color system:

```
01 Primitives  (--mono-*, --brand-*, --accent-*, --support-*, --raw-*)
      ↑ alias
02 Semantic    (--color-*)   ← components only ever reference this layer
```

- **`src/theme.css`** is the single source of truth. It contains every `--mono-*`, `--brand-*`,
  `--raw-*` primitive and every `--color-*` semantic alias.
- The running local Caelo theme at `http://127.0.0.1:5173/` (Vite `npm run dev`) must resolve
  from the same `src/theme.css` token graph. Use the local page as the visual parity reference,
  but use `src/theme.css` as the naming and aliasing authority.
- **`src/theme-riocity.css`** is the read-only name allowlist (318 `--color-*` names). Caelo
  keeps the same names, substitutes Caelo values (blue / white / gold — not Riocity green/dark).
- Components write `var(--color-*)` **only**. They never touch `--mono-*` or hex.
- Figma semantic variables must keep the same API names as local Caelo semantics. Every
  `02 Semantic` variable must map back to the exact local CSS custom property through the naming
  formula below, and its Web code syntax must be `var(--color-...)`. Do not choose a different
  semantic merely because it resolves to the same hex value.
- Figma node bindings must also use the same semantic role as localhost. Do not bind by matching
  the resolved color only. For example, if localhost says `color: var(--color-text-sticky-nav-text)`,
  the Figma text/icon must bind to `color/text/sticky/nav/text`, even if another semantic resolves
  to the same hex.

### Figma ↔ CSS naming formula

Generated by `scripts/parse-theme-css-for-figma.mjs` and inverted by `scripts/figma-path-to-css.mjs`:

```
Figma path (02 Semantic)     →  CSS custom property (WEB code syntax)
mono/700                     →  var(--mono-700)
brand/500                    →  var(--brand-500)
raw/brand/cam                →  var(--raw-brand-cam)
color/surface/base           →  var(--color-surface-base)
color/sticky/nav             →  var(--color-sticky-nav)
color/text/sticky/nav/text     →  var(--color-text-sticky-nav-text)
color/text/primary/card/title  →  var(--color-text-primary-card-title)
```

Rule for `color/*`: strip the `color/` prefix, replace every remaining `/` with `-`, prefix
`--color-` (gradients use `/start` + `/end` stop pairs; see gradient rule below).
Gradient pairs `color/gradient/home/cta/start` + `/end` expose one composite
`--color-gradient-home-cta` in CSS (the `/start` and `/end` live only in Figma as semantic stop pairs).

Every Figma variable must also set **WEB code syntax** to the matching `var(--…)` string. Use
`scripts/figma-path-to-css.mjs` (or `npm run figma:gen-batches` → `07-sync-web-code-syntax-*`) so
Figma Dev Mode shows the same custom property name the site uses.

## 1:1 SEMANTIC BINDING — LOCALHOST → FIGMA

This is the core product rule for page migration: **every painted layer in Figma uses the same
semantic color variable name as the matching element on localhost**, in the **same structural
position** (same section, same sub-component, same role).

### What “1:1” means

| Dimension | Localhost (code) | Figma (design) | Must match? |
|-----------|------------------|----------------|-------------|
| **Semantic name** | `var(--color-sticky-nav)` | Variable `color/sticky/nav` | ✓ Yes — always |
| **WEB code syntax** | `var(--color-sticky-nav)` | Variable WEB field | ✓ Yes — always |
| **Element role** | `.top-sticky-nav-bar` background | Frame `top-sticky-nav-bar` fill | ✓ Yes — same role |
| **Layer position** | Navbar → sticky bar → main row | Frame `Navbar` → `top-sticky-nav-bar` → `top-nav-shell` | ✓ Yes — same hierarchy |
| **Resolved hex** | Computed color at runtime | Default mode alias chain | Helpful for QA only — **not** the binding rule |

**Do not** pick “closest hex” from the variable panel. **Do** trace the React/CSS source and bind
the semantic that the component actually references.

### Binding workflow (per page)

```
1. Open localhost page (e.g. http://127.0.0.1:5173/) at desktop width (1440px).
2. Identify the React component tree for that page (e.g. Navbar, HeroSection, Footer).
3. For each visible element that has a color:
   a. Find the CSS class or Tailwind arbitrary value in JSX (e.g. bg-[var(--color-sticky-nav)]).
   b. If the class is a utility in src/styles/theme.css, read which --color-* it resolves to.
   c. Convert --color-* → Figma path via the naming formula (§ Figma ↔ CSS naming formula).
   d. Create or locate the matching Figma frame/layer at the same position in the page frame.
   e. Bind fill, stroke, or text color to that semantic variable (Default mode).
4. Name Figma layers after the source class or component (see Layer naming below).
5. Run the page binding audit checklist (§ Page binding audit checklist).
```

### Step 3 — Populate `01 Primitives` from `src/theme.css`

For every primitive token (`--mono-*`, `--brand-*`, `--raw-*`, etc.) parsed in Step 0:

1. Convert the CSS name to a Figma path:
   - Strip the leading `--`
   - Replace `-` with `/` only at the **first segment boundary** (the group prefix):
     - `mono-700`   → group `mono`,  name `700`
     - `brand-500`  → group `brand`, name `500`
     - `raw-app-surface-base` → group `raw`, name `app-surface-base`
   - Use Figma's variable group syntax: `"mono/700"`, `"brand/500"`, `"raw/app-surface-base"`

2. Resolve the hex value from `theme.css`. If the value is another `var(--x)`, follow the chain
   inside `theme.css` until you reach a hex/rgba literal. Store that resolved hex.

3. Create or update the variable:

```js
function upsertPrimitive(collection, figmaPath, hexValue) {
  const existing = figma.variables.getLocalVariables("COLOR")
    .find(v => v.variableCollectionId === collection.id && v.name === figmaPath);

  const v = existing ?? figma.variables.createVariable(figmaPath, collection, "COLOR");
  v.setValueForMode(collection.modes[0].modeId, hexToRgb(hexValue));
  return v;
}

// Helper
function hexToRgb(hex) {
  const h = hex.replace("#","");
  const r = parseInt(h.slice(0,2),16)/255;
  const g = parseInt(h.slice(2,4),16)/255;
  const b = parseInt(h.slice(4,6),16)/255;
  const a = h.length === 8 ? parseInt(h.slice(6,8),16)/255 : 1;
  return { r, g, b, a };
}
```

**Gradient stop primitives** — every `--raw-gradient-*-start` / `--raw-gradient-*-end` and
`--raw-scrim-*` hex also lives in `01 Primitives` under group `raw/gradient/` and `raw/scrim/`
respectively. Example:
```
--raw-gradient-promo-card-start: #d8f3ff  →  raw/gradient/promo-card/start
--raw-gradient-promo-card-end:   #a6d7f2  →  raw/gradient/promo-card/end
```

### Step 4 — Populate `02 Semantic` from `src/theme.css`

For every semantic token (`--color-*`) parsed in Step 0:

1. Convert the CSS name to a Figma path:
   - Strip `--color-`, replace remaining `-` with `/`
   - `--color-surface-float`  → `color/surface/float`
   - `--color-text-primary`   → `color/text/primary`
   - `--color-gradient-home-cta` → `color/gradient/home/cta`  *(composite; see gradient rule)*

2. Resolve the **primitive variable** it aliases. In `theme.css` it reads:
   ```css
   --color-surface-float: var(--raw-app-surface-float);
   ```
   Walk the chain: `--raw-app-surface-float` is a primitive in `01 Primitives` →
   `raw/app-surface-float`. Use a **variable alias**, not a hardcoded color:

```js
function upsertSemantic(semCol, figmaPath, primitiveVar, primitiveModeId, defaultModeId, cam88ModeId) {
  const existing = figma.variables.getLocalVariables("COLOR")
    .find(v => v.variableCollectionId === semCol.id && v.name === figmaPath);

  const v = existing ?? figma.variables.createVariable(figmaPath, semCol, "COLOR");

  // Alias to the primitive for both modes (CAM88 override is a separate task)
  const alias = { type: "VARIABLE_ALIAS", id: primitiveVar.id };
  v.setValueForMode(defaultModeId, alias);
  v.setValueForMode(cam88ModeId,   alias);  // same until CAM88 overrides are supplied
  return v;
}
```

3. **Gradient composites** — `--color-gradient-*` maps to a pair of `start`/`end` primitive
   variables. In Figma, create **two** variables inside `02 Semantic`:
   ```
   color/gradient/home/cta/start  →  alias raw/gradient/home-cta/start
   color/gradient/home/cta/end    →  alias raw/gradient/home-cta/end
   ```
   The CSS composite (`linear-gradient(...)`) is **not** a Figma variable — it is assembled in
   CSS only. The Figma variables only hold the two stop colors.

4. **Scopes** — set the correct Figma scope so variables appear in the right pickers:
   - `text/*` → `TEXT_FILL`
   - `surface/*`, `button/*`, `primary`, `accent`, `overlay/*`, `popup/*`, `sticky-nav/*`,
     `scrollbar/*`, `table/*`, `progress/*` → `FRAME_FILL`, `SHAPE_FILL`
   - `border/*` → `STROKE_COLOR`
   - `gradient/*/start`, `gradient/*/end` → `FRAME_FILL`, `SHAPE_FILL`
   - `icon/*` → `FRAME_FILL`, `SHAPE_FILL`
   - Never use `ALL_SCOPES`.

```js
// Example scope assignment
v.scopes = ["TEXT_FILL"];          // for color/text/* variables
v.scopes = ["FRAME_FILL","SHAPE_FILL"]; // for color/surface/* variables
v.scopes = ["STROKE_COLOR"];       // for color/border/* variables
```

## CHAIN RESOLUTION RULES

`theme.css` may chain through multiple `var()` references before reaching a hex.
You must fully resolve each chain **inside `theme.css`** (not across files).

```
--color-surface-base: var(--raw-app-surface-base);
--raw-app-surface-base: #ffffff;
→ resolved hex: #ffffff
→ Figma primitive: raw/app-surface-base  value #ffffff
→ Figma semantic:  color/surface/base    alias → raw/app-surface-base
```

If a semantic resolves to **another semantic** (rare), alias to the intermediate semantic
variable in `02 Semantic`, not to a primitive directly.

```
--color-accent-pale: var(--color-surface-cool-light);
→ Figma: color/accent/pale  ALIAS → color/surface/cool/light  (both in 02 Semantic)
```

## GRADIENT-SPECIFIC RULES

In `theme.css`, gradient composites look like:
```css
--color-gradient-home-cta: linear-gradient(180deg, var(--raw-cta-start) 0%, var(--raw-cta-end) 100%);
```

**In Figma**, do NOT create a single variable with a gradient value.
Instead create **two primitive variables** for the stops:
```
01 Primitives:  raw/cta/start  →  hex from --raw-cta-start
01 Primitives:  raw/cta/end    →  hex from --raw-cta-end
```
And **two semantic variables** that alias them:
```
02 Semantic:  color/gradient/home/cta/start  →  alias raw/cta/start
02 Semantic:  color/gradient/home/cta/end    →  alias raw/cta/end
```
The `linear-gradient(...)` formula stays in CSS only.

## AUDIT SCRIPT (run at end of Step 6)

```js
// Paste into Figma console after migration to verify integrity
(function auditVariables() {
  const allVars = figma.variables.getLocalVariables("COLOR");
  const primitives = allVars.filter(v => {
    const col = figma.variables.getVariableCollectionById(v.variableCollectionId);
    return col?.name === "01 Primitives";
  });
  const semantics = allVars.filter(v => {
    const col = figma.variables.getVariableCollectionById(v.variableCollectionId);
    return col?.name === "02 Semantic";
  });

  let errors = 0;

  semantics.forEach(s => {
    const col = figma.variables.getVariableCollectionById(s.variableCollectionId);
    const defaultMode = col.modes.find(m => m.name === "Default");
    if (!defaultMode) return;
    const val = s.valuesByMode[defaultMode.modeId];
    if (!val || val.type !== "VARIABLE_ALIAS") {
      console.error(`❌ Semantic "${s.name}" has no alias in Default mode`);
      errors++;
    }
  });

  console.log(`✅ Primitives: ${primitives.length}`);
  console.log(`✅ Semantics:  ${semantics.length}`);
  console.log(errors === 0 ? "✅ All semantics correctly aliased." : `❌ ${errors} error(s) found.`);
})();
```
